<div class="postBody"><div> <a href="/blog/fa/dntips-3421/">تا اینجا</a> با کمک توابع توانستیم PowerShell را به اصطلاح extend کنیم. نوع دیگر دستورات، command letها هستند. این نوع دستورات را با کمک یک زبان دات‌نتی میتوانیم ایجاد کنیم. به این نوع دستورات complied cmdlet گفته میشود. در بیشتر مواقع با کمک advanced functionها میتوانید بیشتر کارها را انجام دهید؛ چراکه به صورت مستقیم امکان استفاده از دات‌نت را درون PowerShell دارید. اما شاید ترجیح دهید از سی‌شارپ یا دیگر زبان‌ها دات‌نتی برای ایجاد یک تابع استفاده کنید.</div> <div> <br/> </div> <div> <b>نحوه‌ی ایجاد یک cmdlet با کمک #C</b> </div> <div>ابتدا یک دایرکتوری جدید را ایجاد کرده و درون آن یک پروژه‌ی از نوع class library را ایجاد کنید. سپس پکیج PowerShellStandard.Library را درون پروژه ایجاد شده با کمک dotnet cli به پروژه اضافه کنید:  </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">mkdir ps_cmdlet_with_csharp &amp;&amp; cd "$_"&#10;dotnet new classlib&#10;dotnet add package PowerShellStandard.Library&#10;mv Class1.cs GetHelloCommand.cs</pre>
 </div>
در پایان دستورات فوق، نام فایل پیش‌فرض Class1 را نیز به GetHelloCommand تغییر داده‌ایم. در ادامه محتویات فایل را اینگونه ویرایش خواهیم کرد:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">namespace ps_cmdlet_with_csharp;&#10;using System.Management.Automation;&#10;&#10;[Cmdlet(VerbsCommon.Get, "Hello")]&#10;public class GetHelloCommand : PSCmdlet&#10;{&#10;    [Parameter(Mandatory = true, Position = 0, ValueFromPipeline = true)]&#10;    public string Name { get; set; }&#10;    protected override void BeginProcessing()&#10;    {&#10;        WriteObject("Start processing");&#10;    }&#10;    protected override void ProcessRecord()&#10;    {&#10;        WriteObject("Hello " + Name);&#10;    }&#10;    protected override void EndProcessing()&#10;    {&#10;        WriteObject("End processing");&#10;    }&#10;}</pre>
 </div>
همانطور که مشاهده میکنید، کلاس فوق را از PSCmdlet ارث‌بری کرده‌ایم. در کل برای ایجاد یک command let، از یکی از انواع Cmdlet یا PSCmdlet میتوانیم ارث‌بری کنیم. Cmdlet یک کلاس پایه است که PSCmdlet نیز از آن ارث برده است و یکسری امکانات بیشتری را جهت تعامل با PowerShell ارائه میدهد:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">using System.Collections.ObjectModel;&#10;using System.Management.Automation.Host;&#10;&#10;namespace System.Management.Automation&#10;{&#10;    public abstract class PSCmdlet : Cmdlet&#10;    {&#10;        protected PSCmdlet();&#10;&#10;        public PSEventManager Events { get; }&#10;        public PSHost Host { get; }&#10;        public CommandInvocationIntrinsics InvokeCommand { get; }&#10;        public ProviderIntrinsics InvokeProvider { get; }&#10;        public JobManager JobManager { get; }&#10;        public JobRepository JobRepository { get; }&#10;        public InvocationInfo MyInvocation { get; }&#10;        public PagingParameters PagingParameters { get; }&#10;        public string ParameterSetName { get; }&#10;        public SessionState SessionState { get; }&#10;&#10;        public PathInfo CurrentProviderLocation(string providerId);&#10;        public Collection&lt;string&gt; GetResolvedProviderPathFromPSPath(string path, out ProviderInfo provider);&#10;        public string GetUnresolvedProviderPathFromPSPath(string path);&#10;        public object GetVariableValue(string name);&#10;        public object GetVariableValue(string name, object defaultValue);&#10;    }&#10;}</pre>
 </div>
در نهایت command let باید به یک DLL تبدیل شود؛ چون همانطور که قبلآً نیز اشاره شد، هر command let در واقع یک شیء دات‌نتی است. در ادامه پروژه جاری را بیلد کرده و توسط دستور Import-Module فایل DLL تولید شده را درون Shell ایمپورت خواهیم کرد:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /&gt; dotnet build&#10;PS /&gt; Import-Module ./bin/Debug/net7.0/ps_cmdlet_with_csharp.dll</pre>
 </div>
سپس توسط دستور Get-Command میتوانیم مطمئن شویم که ماژول موردنظر با موفقیت ایمپورت شده‌است:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /&gt; Get-Command -Module ps_cmdlet_with_csharp&#10;&#10;CommandType     Name                                               Version    Source&#10;-----------     ----                                               -------    ------&#10;Cmdlet          Get-Hello                                          1.0.0.0    ps_cmdlet_with_csharp</pre>

همانطور که مشاهده میکنید، درون ماژول ps_cmdlet_with_csharp تنها یک command let تعریف شده‌است. درون یک namespace میتوانیم چندین command let را تعریف کنیم. به عنوان مثال برای مثال قبل میتوانیم:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">namespace ps_cmdlet_with_csharp;&#10;using System.Management.Automation;&#10;&#10;[Cmdlet(VerbsCommon.Get, "Hello")]&#10;public class GetHelloCommand : PSCmdlet&#10;{&#10;    // as before&#10;}&#10;&#10;[Cmdlet(VerbsCommon.Get, "Greetings")]&#10;public class GetGreetingsCommand : PSCmdlet&#10;{&#10;    [Parameter(Mandatory = true, Position = 0, ValueFromPipeline = true)]&#10;    public string Name { get; set; }&#10;    protected override void BeginProcessing()&#10;    {&#10;        WriteObject("Start processing");&#10;    }&#10;    protected override void ProcessRecord()&#10;    {&#10;        WriteObject("Greetings " + Name);&#10;    }&#10;    protected override void EndProcessing()&#10;    {&#10;        WriteObject("End processing");&#10;    }&#10;}</pre>

اکنون اگر پروژه را بیلد کنیم و ماژول بیلد شده را ایمپورت کنیم، با خطای زیر مواجه خواهیم شد:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">

 </div> <div> <br/> </div> <div> <b>یک مثال تکمیلی</b> </div> <div>درون یک کلاس Cmdlet، امکان استفاده از تمامی annotationهایی را که در قسمت قبل بررسی کردیم، اینجا نیز در اختیار داریم؛ بنابراین نیاز به توضیح مجدد آن نیست. در ادامه میخواهیم یک دستور را با عنوان Push-SlackMessage تهیه کنیم که کار ارسال یک پیام را به یک کانال Slack، انجام میدهد:  </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">namespace ps_cmdlet_with_csharp;&#10;using System.Management.Automation;&#10;using System.Net.Http.Headers;&#10;&#10;&#10;[Cmdlet(VerbsCommon.Push, "SlackMessage")]&#10;[Alias("ssm")]&#10;[OutputType(typeof(string))]&#10;public class SlackMessageCommand : PSCmdlet&#10;{&#10;    [Parameter(Mandatory = true)]&#10;    [Alias("m")]&#10;    public string Message { get; set; }&#10;&#10;    [Parameter(Mandatory = true)]&#10;    [Alias("t")]&#10;    [ValidatePattern(@"xoxp-[0-9]{11}-[0-9]{12}-[0-9]{13}-[0-9a-zA-Z]{32}")]&#10;    public string Token { get; set; }&#10;&#10;    [Parameter(Mandatory = true)]&#10;    [Alias("cid")]&#10;    public string ChannelID { get; set; }&#10;    protected async override void ProcessRecord()&#10;    {&#10;        base.ProcessRecord();&#10;        try&#10;        {&#10;            using var client = new HttpClient();&#10;            client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", this.Token);&#10;            var values = new Dictionary&lt;string, string&gt;&#10;            {&#10;                { "channel", this.ChannelID },&#10;                { "text", this.Message }&#10;            };&#10;            var content = new FormUrlEncodedContent(values);&#10;            var response = await client.PostAsync("https://slack.com/api/chat.postMessage", content);&#10;            var responseString = await response.Content.ReadAsStringAsync();&#10;            WriteObject("Message sent");&#10;        }&#10;        catch (Exception ex)&#10;        {&#10;            WriteObject(ex.Message);&#10;        }&#10;    }&#10;}</pre>
 </div> <div> <b> <br/> </b> </div> <div> <b>یک نکته در مورد ایمپورت کردن ماژول‌ها</b> </div> <div>دستوراتی که تاکنون ایجاد کردیم (هم توابع و هم compiled cmletها) برای اجرا باید یکبار درون حافظه قرار بگیرند و سپس امکان اجرای آنها را خواهیم داشت. دلیل آن نیز این است که همه چیز درون سشن جاری انجام خواهد شد و به محض بستن آن، تغییرات نیز ار حافظه خارج خواهند شد. یعنی برای command letی که ایجاد کردیم، با هربار باز کردن یک سشن جدید مجبور خواهیم بود که مجدداً آن را ایمپورت کنیم. برای رفع این مشکل میتوانیم از پروفایل‌ها استفاده کنیم. توسط پروفایل، امکان سفارشی‌سازی شل را خواهیم داشت. پروفایل در واقع یک اسکریپت PowerShell است که به محض اجرای PowerShell فراخوانی خواهد شد. بنابراین درون پروفایل این فرصت را خواهیم داشت تا متغیرها، ماژول‌ها، aliaseها و… را قبل از باز کردن شل، درون سشن PowerShell بارگذاری کنیم.
