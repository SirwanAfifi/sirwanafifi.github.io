<div class="postBody">در مطلب <a href="/blog/fa/dntips-3227/">قبل</a> نحوه‌ی ایجاد روابط Polymorphic را بررسی کردیم و همچنین چندین راه‌حل جایگزین را نیز ارائه دادیم. همانطور که عنوان شد این نوع روابط اساساً از لحاظ طراحی دیتابیس اصولی نیستند و تا حد امکان نباید استفاده شوند. این نوع روابط بیشتر ORM friendly هستند و اکثر فریم‌ورک‌های غیردات‌نتی به عنوان یک گزینه‌ی توکار، امکان ایجاد این روابط را فراهم میکنند. به عنوان مثال در<a href="https://laravel.com/docs/7.x/eloquent-relationships#polymorphic-relationships">Laravel Eloquent ORM</a> به صورت توکار از این قابلیت پشتیبانی می‌شود: <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">&lt;?php&#10;&#10;namespace App;&#10;&#10;use Illuminate\Database\Eloquent\Model;&#10;&#10;class Comment extends Model&#10;{&#10;    /**&#10;     * Get the owning commentable model.&#10;     */&#10;    public function commentable()&#10;    {&#10;        return $this-&gt;morphTo();&#10;    }&#10;}&#10;&#10;class Post extends Model&#10;{&#10;    /**&#10;     * Get all of the post's comments.&#10;     */&#10;    public function comments()&#10;    {&#10;        return $this-&gt;morphMany('App\Comment', 'commentable');&#10;    }&#10;}&#10;&#10;class Video extends Model&#10;{&#10;    /**&#10;     * Get all of the video's comments.&#10;     */&#10;    public function comments()&#10;    {&#10;        return $this-&gt;morphMany('App\Comment', 'commentable');&#10;    }&#10;}</pre>
 </div> <br/> </div> <div>اما در Entity Framework Core هنوز این قابلیت پیاده‌سازی نشده است. در <a href="https://github.com/dotnet/efcore/issues/7623">اینجا</a> می‌توانید وضعیت پیاده‌سازی Polymorphic Association را پیگیری کنید. پیاده‌سازی این قابلیت از این جهت مهم است که امکان کوئری نویسی را برای این نوع روابط ساده‌تر خواهد کرد به عنوان مثال در کدهای PHP فوق جهت واکشی کامنت‌های یک مطلب می‌توانیم اینگونه عمل کنیم: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">$post = App\Post::find(1);&#10;&#10;foreach ($post-&gt;comments as $comment) {&#10;    //&#10;}</pre>
 </div> <br/> </div> <div>همچنین امکان واکشی owner این رابطه را نیز حین کار با کامنت‌ها را خواهیم داشت: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">$comment = App\Comment::find(1);&#10;&#10;$commentable = $comment-&gt;commentable;</pre>
 </div> <br/> </div> <div>در ادامه می‌خواهیم معادل LINQ آن را پیاده‌سازی کنیم. در مطلب قبل مدل Comment این چنین ساختاری داشت: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">public enum CommentType&#10;{&#10;    Article,&#10;    Video,&#10;    Event&#10;}&#10;&#10;public class Comment&#10;{&#10;    public int Id { get; set; }&#10;    public string CommentText { get; set; }&#10;    public string User { get; set; }&#10;    public int? TypeId { get; set; }&#10;    public CommentType CommentType { get; set; }&#10;}</pre>
 </div> <br/> </div> <div>در اینجا همانطور که مشاهده میکنید هیچگونه ارتباط معناداری بین Comment و همچنین owner رابطه (که ممکن است هر کدام از مقادیر Enum فوق باشد) وجود ندارد. اگر این مدل به تنها یک مدل مثلاً Article اشاره داشته باشد، نیاز به تعیین Navigation Property در دو طرف رابطه خواهد بود: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">public class Comment&#10;{&#10;    public int Id { get; set; }&#10;    public string CommentText { get; set; }&#10;    public string User { get; set; }&#10;&#10;    public virtual Article Article { get; set; }&#10;    public int ArticleId { get; set; }&#10;}&#10;&#10;public class Article&#10;{&#10;    public int Id { get; set; }&#10;    public string Title { get; set; }&#10;    public string Slug { get; set; }&#10;    public string Description { get; set; }&#10;    &#10;    public virtual ICollection&lt;Article&gt; Articles { get; set; }&#10;}</pre>
 </div> <br/> </div> <div>اما از آنجائیکه رابطه یک حالت پویا دارد، نمی‌توانیم به صورت صریح نوع ارجاعات را در دو طرف رابطه تعیین کنیم. برای داشتن همچین قابلیتی می‌توانیم Navigation Property را به صورت [NotMapped] تعیین کنیم که EF Core آنها را در نظر نگیرید. بنابراین به صورت دستی عملکرد آنها را پیاده‌سازی خواهیم کرد. برای اینکار می‌توانیم یک اینترفیس با عنوان ICommentable را تعریف کنیم و برای هر مدلی که نیاز به قابلیت کامنت دارد، این اینترفیس را پیاده‌سازی کنیم. همچنین یک ارجاع به لیستی از کامنت‌ها را به صورت Navigation Property به هر کدام از مدلها نیز اضافه خواهیم کرد:  </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">interface ICommentable&#10;{&#10;    int Id { get; set; }&#10;}&#10;&#10;public class Article : ICommentable&#10;{&#10;    public int Id { get; set; }&#10;    public string Title { get; set; }&#10;    public string Slug { get; set; }&#10;    public string Description { get; set; }&#10;    &#10;    [NotMapped]&#10;    public ICollection&lt;Comment&gt; Comments { get; set; }&#10;}&#10;&#10;public class Video : ICommentable&#10;{&#10;    public int Id { get; set; }&#10;    public string Url { get; set; }&#10;    public string Description { get; set; }&#10;    &#10;    [NotMapped]&#10;    public ICollection&lt;Comment&gt; Comments { get; set; }&#10;}&#10;&#10;public class Event : ICommentable&#10;{&#10;    public int Id { get; set; }&#10;    public string Name { get; set; }&#10;    public DateTimeOffset? Start { get; set; }&#10;    public DateTimeOffset? End { get; set; }&#10;    &#10;    [NotMapped]&#10;    public ICollection&lt;Comment&gt; Comments { get; set; }&#10;}</pre>
 </div> <br/> </div> <div>سپس درون مدل Comment ارجاع به Polymorphic relation را نیز به صورت [NotMapped] پیاده‌سازی خواهیم کرد: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">public class Comment&#10;{&#10;    public int Id { get; set; }&#10;    public string CommentText { get; set; }&#10;    public string User { get; set; }&#10;    public int? TypeId { get; set; }&#10;    public CommentType CommentType { get; set; }&#10;&#10;    ICommentable _parent;&#10;&#10;    [NotMapped]&#10;    public ICommentable Parent&#10;    {&#10;        get =&gt; _parent;&#10;        set&#10;        {&#10;            _parent = value;&#10;            TypeId = value.Id;&#10;            CommentType = (CommentType) Enum.Parse(typeof(CommentType), value.GetType().Name);&#10;        }&#10;    }&#10;}</pre>
 </div> <br/> </div> <div>کاری که در بالا انجام شده، تنظیم تایپ مدلی است که می‌خواهیم واکشی کنیم. یعنی به محض مقداردهی، پراپرتی Comments مدل مورد نظر به همراه Id و در نهایت نوع آن را تنظیم کرده‌ایم. اکنون برای واکشی کامنت‌های یک مطلب خواهیم داشت: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">var article = dbContext.Articles.Find(1);&#10;            &#10;article.Comments = dbContext.Comments&#10;    .Where(c =&gt; c.TypeId == article.Id&#10;                &amp;&amp; c.CommentType == CommentType.Article)&#10;    .ToList();&#10;&#10;foreach (var comment in article.Comments)&#10;    comment.Parent = article;&#10;&#10;foreach (var comment in article.Comments)&#10;{&#10;    Console.WriteLine($"{comment.User} - ${comment.CommentText} - {((Article) comment.Parent).Title}");&#10;}</pre>
 </div> <br/> </div> <div>همانطور که مشاهده می‌کنید اکنون می‌توانیم از هر دو طرف رابطه به اطلاعات موردنیازمان دسترسی داشته باشیم.</div></div>
