<div class="postBody">استفاده از Redux درون پروژه‌های React، به روش‌های مختلفی قابل انجام است؛ یعنی محدودیتی از لحاظ نحوه چیدمان فایل‌ها، تغییر state و نحوه‌ی dispatch کردن action وجود ندارد. به عبارتی این آزادی عمل را خواهیم داشت تا خودمان سیم‌کشی پروژه را انجام دهیم؛ ولی مشکل اصلی اینجاست که نمی‌توانیم مطمئن شویم روشی که پروژه را با آن ستاپ کرده‌ایم آیا به عنوان یک best-practice محسوب می‌شود یا خیر. در نهایت خروجی را که خواهیم داشت، حجم انبوهی از کدهای boilerplate و پکیج‌های زیادی است که در حین توسعه‌ی پروژه، به همراه Redux اضافه شده‌اند. همچنین در نهایت یک store پیچیده را خواهیم داشت که مدیریت آن به مراتب سخت خواهد شد. یک مشکل دیگر این است که روال گفته شده را باید به ازای هر پروژه‌ی جدید تکرار کنیم. برای حل این مشکل، یکی از maintainerهای اصلی تیم ریداکس، یک پروژه را تحت عنوان <a href="https://github.com/reduxjs/redux-toolkit">Redux Toolkit</a>، مدتها قبل برای حل مشکلات عنوان شده شروع کرده است و این پکیج، جدیداً به قالب رسمی create-react-app اضافه شده است. که در واقع یک روش استاندارد و به اصطلاح opinionated برای ایجاد پروژه‌های ریداکسی می‌باشد و شامل تمامی وابستگی‌های موردنیاز برای کار با Redux از قبیل redux-thunk و همچنین Redux DevTools است.  <div> <br/> </div> <div> <div> <b> ایجاد یک برنامه‌ی خالی React با قالب redux</b> </div> <div>در ادامه برای بررسی این قالب جدید، یک پروژه‌ی جدید React را ایجاد خواهیم کرد:</div> <div> <div align="left" dir="ltr" style="direction: ltr;"> </div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">&gt; npx create-react-app redux-template --template redux&#10;&gt; cd redux-template&#10;&gt; yarn start</pre>
 </div> <br/> </div> <div> <p style="margin-left: auto; margin-right: auto;"> <img src="/img/dntips/a28b932c20a5b9ecd012.png" style="display: block; margin-left: auto; margin-right: auto; cursor: default; height: 511px;"/> </p> </div> <div> <br/> </div> <div> <b>بررسی ساختار پروژه‌ی ایجاد شده<br/> </b> </div> <div>ساختار پروژه‌ی ایجاد شده به صورت زیر است:</div> <div> <p style="margin-left: auto; margin-right: auto;"> </p> </div> <div> <p style="margin-left: auto; margin-right: auto;"> <img src="/img/dntips/bc24c670a019fdf53893.png" style="display: block; margin-left: auto; margin-right: auto; cursor: default; height: 462px;"/> </p> </div> <div> <br/> </div> <div>این ساختار خیلی شبیه به قالب پیش‌فرض create-react-app می‌باشد. همانطور که در تصویر فوق نیز مشاهده میکنید، پروژه‌ی ایجاد شده‌ی با قالب redux (تصویر سمت چپ)، یک فایل با نام store و همچنین یک دایرکتوری را به نام features دارد. اگر به فایل store.js مراجعه کنید، خواهید دید که تنظیمات اولیه‌ی ایجاد store را در قالب یک مثال Counter ایجاد کرده‌است: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="JScript" name="code">import { configureStore } from '@reduxjs/toolkit';&#10;import counterReducer from './features/counter/counterSlice';&#10;&#10;export default configureStore({&#10;  reducer: {&#10;    counter: counterReducer,&#10;  },&#10;});</pre>
 </div>
در کد فوق، نحوه‌ی ایجاد store، نسبت به حالت معمول، خیلی تمیزتر است. نکته‌ی جالب این است که به همراه کد فوق، Redux DevTools و همچنین redux-thunk هم از قبل تنظیم شده‌اند و در نتیجه، نیازی به تنظیم و نصب آنها نیست. تغییر مهم دیگر، پوشه‌ی <a href="https://reactjs.org/docs/faq-structure.html">features</a> می‌باشد که یک روش رایج برای گروه‌بندی کامپوننت‌ها، همراه با فایل‌های وابسته‌ی آن‌ها است. درون این پوشه، یک پوشه جدید را تحت عنوان counter داریم که حاوی فایل‌های زیر می‌باشد:  </div> <div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">Counter&#10;Counter.module.css&#10;counterSlice.js</pre>
 </div>
Counter.js، کامپوننتی است که در نهایت درون صفحه رندر خواهد شد. درون این فایل با استفاده از <a href="https://www.dntips.ir/post/3163">Redux Hooks</a> کار اتصال به store و همچنین dispatch کردن اکشن‌ها انجام گرفته است:</div> <div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="JScript" name="code">import React, { useState } from 'react';&#10;import { useSelector, useDispatch } from 'react-redux';&#10;import {&#10;  decrement,&#10;  increment,&#10;  incrementByAmount,&#10;  selectCount,&#10;} from './counterSlice';&#10;import styles from './Counter.module.css';&#10;&#10;export function Counter() {&#10;  const count = useSelector(selectCount);&#10;  const dispatch = useDispatch();&#10;  const [incrementAmount, setIncrementAmount] = useState(2);&#10;&#10;  return (&#10;    &lt;div&gt;&#10;      &lt;div className={styles.row}&gt;&#10;        &lt;button&#10;          className={styles.button}&#10;          aria-label="Increment value"&#10;          onClick={() =&gt; dispatch(increment())}&#10;        &gt;&#10;          +&#10;        &lt;/button&gt;&#10;        &lt;span className={styles.value}&gt;{count}&lt;/span&gt;&#10;        &lt;button&#10;          className={styles.button}&#10;          aria-label="Decrement value"&#10;          onClick={() =&gt; dispatch(decrement())}&#10;        &gt;&#10;          -&#10;        &lt;/button&gt;&#10;      &lt;/div&gt;&#10;      &lt;div className={styles.row}&gt;&#10;        &lt;input&#10;          className={styles.textbox}&#10;          value={incrementAmount}&#10;          onChange={e =&gt; setIncrementAmount(e.target.value)}&#10;        /&gt;&#10;        &lt;button&#10;          className={styles.button}&#10;          onClick={() =&gt;&#10;            dispatch(&#10;              incrementByAmount({ amount: Number(incrementAmount) || 0 })&#10;            )&#10;          }&#10;        &gt;&#10;          Add Amount&#10;        &lt;/button&gt;&#10;      &lt;/div&gt;&#10;    &lt;/div&gt;&#10;  );&#10;}</pre>
 </div> </div> <div> <br/> </div> <div>فایل Counter.module.css نیز در واقع استایل‌های مربوط به کامپوننت فوق میباشد که به صورت CSS module اضافه شده‌است. در نهایت فایل counterSlice.js را داریم که  کار همان reducer سابق را برایمان انجام خواهد داد؛ اما اینبار با یک ساختار جدید و تحت عنوان slice. اگر به فایل عنوان شده مراجعه کنید، کدهای زیر را خواهید دید:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="JScript" name="code">import { createSlice } from '@reduxjs/toolkit';&#10;&#10;export const slice = createSlice({&#10;  name: 'counter',&#10;  initialState: {&#10;    value: 0,&#10;  },&#10;  reducers: {&#10;    increment: state =&gt; {&#10;      // Redux Toolkit allows us to 'mutate' the state. It doesn't actually&#10;      // mutate the state because it uses the immer library, which detects&#10;      // changes to a "draft state" and produces a brand new immutable state&#10;      // based off those changes&#10;      state.value += 1;&#10;    },&#10;    decrement: state =&gt; {&#10;      state.value -= 1;&#10;    },&#10;    incrementByAmount: (state, action) =&gt; {&#10;      state.value += action.payload.amount;&#10;    },&#10;  },&#10;});&#10;&#10;export const selectCount = state =&gt; state.counter.value;&#10;export const { increment, decrement, incrementByAmount } = slice.actions;&#10;&#10;export default slice.reducer;</pre>
 </div> </div> <div>در این قالب جدید، ترکیب این قطعات هستند که شیء اصلی یا در واقع همان state کلی پروژه را تشکیل خواهند داد. همانطور که مشاهده میکنید، برای ایجاد یک قطعه جدید، از تابع createSlice استفاده شده است. این تابع، تعدادی پارامتر را از ورودی دریافت می‌کند:</div> <ul> <li> <b>name</b>: برای هر بخش از state، می‌توانیم یک نام را تعیین کنیم و این همان عنوانی خواهد بود که می‌توانید توسط Redux DevTools مشاهده کنید. </li> <li> <b>initialValue</b>: در اینجا می‌توانیم مقادیر اولیه‌ای را برای این بخش از state، تعیین کنیم که در مثال فوق، value به مقدار صفر تنظیم شده‌است. </li> <li> <b>reducers</b>: این قسمت محل تعریف actionهایی هستند که قرار است state را تغییر دهند. نکته جالب توجه این است که state در هر کدام از متدهای فوق، به ظاهر mutate شده است؛ اما همانطور که به صورت کامنت نیز نوشته‌است، در پشت صحنه از کتابخانه‌ای با عنوان <a href="https://github.com/immerjs/immer">immer</a> استفاده می‌کند که در عمل بجای تغییر state اصلی، یک کپی از state جدید را جایگزین state قبلی خواهد کرد.</li> </ul> </div> <div>توسط selectCount نیز کار انتخاب مقدار موردنظر از state انجام شده‌است که معادل همان mapPropsToState است و در اینجا امکان دسترسی به state ذخیره شده در مخزن redux فراهم شده است. همچنین در خطوط پایانی فایل نیز اکشن‌ها برای دسترسی ساده‌تر به درون کامپوننت، به صورت Object Destructuring به بیرون export شده‌اند. در نهایت reducer نهایی را از slice ایجاد شده استخراج کرده‌ایم. این پراپرتی برای ایجاد store مورداستفاده قرار می‌گیرد.<br/> </div> <div> <br/> </div> <div> <div> <b>چرا قالب Redux Toolkit از immer برای تغییر state استفاده میکند؟</b> </div> </div> <div>همانطور که در <a href="https://www.dntips.ir/post/3159">این</a> قسمت از سری Redux توضیح داده شد، اعمال تغییرات بر روی آرایه‌ها و اشیاء، باعث ایجاد ناخالصی خواهد شد؛ بنابراین به جای تغییر شیء اصلی، باید توسط یکی از روش‌های Object.assign و یا spread operator، یک clone از state اصلی را ایجاد کرده و آن را به عنوان state نهایی لحاظ کنیم. اما در حین کار با اشیاء nested، انجام اینکار سخت خواهد شد و همچنین خوانایی کد را نیز کاهش می‌دهد:</div> <div> <div align="left" dir="ltr" style="direction: ltr;"> </div> <div align="left" dir="ltr" style="direction: ltr;"> </div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">return {&#10;    ...state,&#10;    models: state.models.map(c =&gt;&#10;        c.model === action.payload.model&#10;          ? {&#10;              ...c,&#10;              on: action.payload.toggle&#10;            }&#10;          : c&#10;      )&#10;  };</pre>
 </div> </div> <div>اما با کمک immer می‌توانیم به صورت مستقیم state را تغییر دهیم:</div> <div> <div align="left" dir="ltr" style="direction: ltr;"> </div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="JScript" name="code">state.models.forEach(item =&gt; {&#10;    if (item.model === action.payload.model) {&#10;      item.on = action.payload.toggle;&#10;    }&#10; });</pre>
 </div>
کاری که immer انجام می‌دهد، تغییر یک شیء، به صورت مستقیم نیست؛ در واقع یک draftState را ایجاد خواهد کرد که در عمل یک proxy برای state فعلی می‌باشد. یعنی با mutate کردن state، یک شیء جدید را در نهایت clone خواهد کرد و به عنوان state نهایی برمی‌گرداند.</div> </div> </div></div>
