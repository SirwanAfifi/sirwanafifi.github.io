<div class="postBody">تا قبل از <a href="https://www.dntips.ir/post/2290">ES 6</a> در جاوا اسکریپت از توابع جهت ایجاد کامپوننت‌هایی با قابلیت استفاده مجدد استفاده می‌شد. این امر برای برنامه‌نویسانی که با زبان‌های OOP آشنایی دارند، شاید چندان خوشایند نباشد. در TypeScript نیز همانند ES 6 امکان استفاده از <a href="https://www.dntips.ir/post/2300">کلاس‌ها</a> مهیا است.<div>در حالت کلی یک کلاس قالبی برای ایجاد اشیاء است. تمامی اشیاء ایجاد شده از این الگو دارای یکسری پراپرتی و متد می‌باشند. از پراپرتی‌ها جهت تعریف وضعیت‌ها و از متدها جهت تعریف رفتارها استفاده خواهد شد. همچنین مزیت اصلی یک کلاس، کپسوله‌سازی قابلیت‌های یک موجودیت خاص است. همانند دیگر زبان‌های شیءگرا، در TypeScript نیز یک کلاس می‌تواند ویژگی‌های زیر را داشته باشد:</div> <div> <ul> <li>سازنده (constructor)<br/> </li> <li>پراپرتی، متد</li> <li>Access Modifiers<br/> </li> <li>ارث‌بری<br/> </li> <li>کلاس‌های Abstract<br/> </li> </ul> <div>در ادامه هر کدام از موارد فوق را بررسی خواهیم کرد.</div> <div> <b> <br/>
سازنده (Constructor)</b> </div> <div>از سازنده‌ها جهت مقداردهی وهله‌های یک کلاس استفاده می‌شود. در ادامه یک کلاس جدید را با استفاده از کلمه‌ی کلیدی class ایجاد کرده‌ایم. این کلاس دارای یک سازنده است:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="TypeScript" name="code">class ReferenceItem {&#10;    constructor(title: string, publisher?: string) {&#10;        // perform initialization here&#10;    }&#10;}</pre>
 </div>
همانطور که مشاهده می‌کنید یک سازنده شبیه به یک متد است؛ با این تفاوت که برای نام آن از کلمه کلیدی constructor استفاده می‌شود. در TypeScript برای یک کلاس تنها یک سازنده را می‌توانیم داشته باشیم. البته در دیگر زبان‌های برنامه‌نویسی امکان تعریف چندین سازنده را با پارامترهای مختلف برای یک کلاس می‌توانید داشته باشید. برای رسیدن به این هدف در TypeScript می‌توان از <a href="/blog/fa/dntips-2351/">Optional Parameters</a> استفاده کرد. برای ایجاد یک وهله از کلاس فوق می‌توانیم به این صورت عمل کنیم:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="TypeScript" name="code">let encyclopedia = new ReferenceItem('WorldPedia', 'WorldPub');</pre>
 </div>
در کد فوق با استفاده از کلمه‌ی کلیدی new یک وهله از کلاس ReferenceItem را ایجاد کرده‌ایم و در نهایت آن را به متغیری با نام encyclopedia انتساب داده‌ایم. یعنی در واقع با استفاده از new توانسته‌ایم سازنده‌ی کلاس را فراخوانی کرده و سپس وهله‌ایی از آن را به متغیر ذکر شده انتساب دهیم.</div> <div> <b> <br/>
پراپرتی، متد </b> </div> <div>همانند <a href="https://www.dntips.ir/post/2352">اینترفیس‌ها</a>، کلاس‌ها نیز می‌توانند پراپرتی و متد داشته باشند. با این تفاوت که در کلاس‌ها جزئیات پیاده‌سازی نیز ذکر خواهد شد. در یک کلاس به دو روش متفاوت می‌توانیم پراپرتی را تعریف کنیم. روش اول همانند تعریف یک <a href="https://www.dntips.ir/post/2349">متغیر</a> است. به عنوان مثال در کلاس زیر یک پراپرتی با نام numberOfPages را از نوع عددی تعریف کرده‌ایم:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="TypeScript" name="code">class ReferenceItem {&#10;    numberOfPages: number;&#10;}</pre>
 </div>
برای دسترسی به این پراپرتی می‌توانیم از سینتکس نقطه (.) استفاده کنیم. روش دوم برای تعریف یک پراپرتی، ایجاد accessor‌های سفارشی است. accessors در واقع توابع getter و setter هستند که به شما در نحوه‌ی get و set کردن یک پراپرتی کمک خواهند کرد:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="TypeScript" name="code">class ReferenceItem {&#10;    numberOfPages: number;&#10;    &#10;    get editor(): string {&#10;        // custom getter logic goes here, should return a value&#10;    }&#10;    &#10;    set editor(newEditor: string) {&#10;        // custom setter logic goes here&#10;    }&#10;}</pre>
 </div>
همانطور که مشاهده می‌کنید، accessorهایی را برای پراپرتی editor با استفاده از کلمات کلیدی get و set ایجاد کرده‌ایم. این accessorها در واقع توابعی همنام هستند. تابع get همیشه فاقد پارامتر است. می‌توانیم برای تابع get نوع برگشتی را نیز تعیین کنیم (به عنوان مثال در کد فوق نوع برگشتی string است). setter نیز باید تنها یک پارامتر از ورودی دریافت کند. همچنین نمی‌توانیم برای آن نوع برگشتی را تعیین کنیم. درون بدنه‌ی این accessorها می‌توانیم هر نوع کنترلی را بر روی پراپرتی داشته باشیم. برای دسترسی این accessorها نیز باید از سینتکس نقطه (.) استفاده کنیم.</div> <div>متدها نیز توابعی هستند که درون یک کلاس تعریف می‌شوند. برای نمونه در کد زیر یک تابع با نام printChapterTitle را تعریف کرده‌ایم که یک پارامتر را از ورودی دریافت کرده و هیچ مقداری را در خروجی بر نمی‌گرداند:</div> <div> <div align="left" dir="ltr" style="direction: ltr;"> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">class ReferenceItem {&#10;    numberOfPages: number;&#10;    &#10;    get editor(): string {&#10;        // custom getter logic goes here, should return a value&#10;    }&#10;    &#10;    set editor(newEditor: string) {&#10;        // custom setter logic goes here&#10;    }&#10;    &#10;    printChapterTitle(chapterNum: number): void {&#10;        // print title here&#10;    }&#10;}</pre>
 </div> </div> <b> <div> <b> <br/> </b> </div>
Parameter properties <br/> </b> </div> <div>در حالت عادی برای مقداردهی اولیه‌ی پراپرتی‌ها یک شیء می‌توانیم یکسری پارامتر را برای سازنده کلاس تعریف کرده و درون سازنده، پراپرتی‌های موردنیازمان را مقداردهی کنیم:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="TypeScript" name="code">class Author {&#10;    name: string;&#10;    &#10;    constructor(authorName: string) {&#10;        name = authorName;&#10;    }&#10;}</pre>
 </div>
با کمک Parameter properties می‌توانیم به صورت خلاصه‌تری اینکار را انجام دهیم:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">class Author {&#10;    constructor(public name: string){}&#10;}</pre>
 </div>
همانطور که مشاهده می‌کنید اینکار را با افزودن کلمه‌ی کلیدی public به ابتدای پارامتر name انجام داده‌ایم. در این‌حالت دیگر نیازی به تعریف یک پراپرتی اضافی درون کلاس نخواهیم داشت. کامپایلر TypeScript خودش یک پراپرتی را با همین نام ایجاد کرده و مقدار دریافتی از سازنده را برای آن ست خواهد کرد.</div> <div> <b> <br/> </b> </div> <div> <b>Static Properties</b> </div> <div>تاکنون درباره‌ی اعضای مربوط به هر وهله از کلاس‌ها صحبت کردیم؛ یعنی اعضایی که در زمان وهله‌سازی در دسترس خواهند بود. در واقع می‌توانیم اعضای استاتیک را نیز برای کلاس‌ها داشته باشیم. منظور از استاتیک این است که مقادیر یک عضوء استاتیک در وهله‌های مختلف یک شیء، متفاوت نیست. بلکه یک مقدار آن برای تمامی وهله‌ها به اشتراک گذاشته خواهد شد:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="TypeScript" name="code">class Library {&#10;    constructor(public name: string) {}&#10;    &#10;    static description: string = 'A source of knowledge';&#10;}&#10;&#10;let lib = new Library('New York Public Library');&#10;console.log(lib.name); // available on instances of the class&#10;&#10;console.log(Library.description);</pre>
 </div> <b> <div> <b> <br/> </b> </div>
Access Modifiers</b> </div> <div>با استفاده از Access Modifier می‌توانیم میدان دید یک پراپرتی و یا یک متد را برای مصرف کننده‌ی کلاس کنترل کنیم. TypeScript دارای سه Access Modifier است:</div> <div> <b>public</b>: در حالت پیش‌فرض تمامی اعضای یک کلاس عمومی (public) هستند. در نتیجه لزومی به ذکر آن برای پراپرتی‌ها و متدها نیست. یک حالت استثناء، استفاده از Parameter properties است. در این حالت باید کلمه‌ی کلیدی public حتماً ذکر شود.  </div> <div> <b>private</b>: برای محدود کردن دسترسی اعضای یک کلاس می‌توانید از کلمه‌ی کلیدی private استفاده کنید. در این‌حالت مصرف کننده‌ی کلاس به اعضای خصوصی (private) دسترسی نخواهد داشت.  </div> <div> <b>protected</b>: این modifier نیز شبیه به private عمل می‌کند، با این تفاوت که توسط subclassهای مربوط به کلاس تعریف شده در آن نیز قابل دسترس است.</div> <div> <b> <br/> </b> </div> <div> <b> <br/> </b> </div> <div> <b>Inheritance</b> </div> <div>منظور از Inheritance یا ارث‌بری، اشتراک‌گذاری تعاریف یک کلاس برای یک یا چند sub-class است. فرض کنید یک کلاس با نام ReferenceItem با یکسری اعضای تعریف شده درون آن داریم و می‌خواهیم دو کلاس مشتق شده را از این کلاس تهیه کنیم. در این‌حالت کلاس ReferenceItem کلاس پایه (base class) و کلاس‌های مشتق شده از آن sub-class نامیده می‌شوند. بنابراین وهله‌های ایجاد شده از کلاس‌های مشتق شده دارای پراپرتی‌های کلاس پایه نیز خواهند بود. برای داشتن قابلیت ارث‌بری در TypeScript می‌توانیم به اینصورت عمل کنیم:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="TypeScript" name="code">class ReferenceItem {&#10;    title: string;&#10;    printItem(): void { &#10;        // print something here &#10;    }&#10;}&#10;&#10;class Journal extends ReferenceItem {&#10;    constructor() {&#10;        super();&#10;    }&#10;    &#10;    contributors: string[];&#10;}</pre>
 </div>
همانطور که مشاهده می‌کنید با استفاده از کلمه‌ی کلیدی extends توانسته‌ایم یک sub-class ایجاد کنیم. بنابراین وهله‌های کلاس Journal علاوه بر پراپرتی‌های خود (در اینجا contributors ) دارای پراپرتی title و همچنین متد printItem نیز هستند. نکته‌ایی که در اینجا وجود دارد این است که تمامی sub-classها یا کلاس‌های مشتق شده باید درون سازنده‌ی خود، تابع super را فراخوانی کنند؛ با اینکار سازنده‌ی کلاس پایه فراخوانی خواهد شد.</div> <div>لازم به ذکر است که می‌توان متدهای کلاس پایه را درون کلاس‌های مشتق شده، override کرد. برای اینکار کافی است متد موردنظر در کلاس پایه را درون کلاس مشتق شده مجدداً تعریف کرده و منطق موردنظر را درون آن نوشت:</div> <div> <div align="left" dir="ltr" style="direction: ltr;"> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">class Journal extends ReferenceItem {&#10;    constructor() {&#10;        super();&#10;    }&#10;    &#10;    printItem(): void { &#10;        super.printItem();&#10;        console.log('message from Journal');&#10;    }&#10;    &#10;    contributors: string[];&#10;}</pre>
 </div> </div>
با استفاده از super.printItem به کامپایلر TypeScript گفته‌ایم که تمامی کدهای درون متد printItem در کلاس پایه نیز اجرا شوند. اگر مایل بودید می‌توانید از آن صرفنظر کنید.</div> <div> <b> <br/> </b> </div> <div> <b>Abstract Classes  </b> <br/> </div> <div>کلاس‌های Abstract یک نوع خاص از کلاس‌ها هستند که نمی‌توان آنها را وهله‌سازی کرد. یعنی تنها برای تعریف کلاس‌های پایه از آنها استفاده خواهد شد. این نوع کلاس‌ها شبیه به <a href="https://www.dntips.ir/post/2352">اینترفیس‌ها</a> هستند؛ اما ممکن است دارای پیاده‌سازی نیز باشند. در ادامه یک نمونه از abstract class را مشاهده می‌کنید:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="TypeScript" name="code">abstract class ReferenceItem {&#10;    private _publisher: string;&#10;    static departement: string = 'Research';&#10;    &#10;    constructor(public title: string, protected year: number) {&#10;        &#10;    }&#10;    &#10;    printItem(): void {&#10;        console.log('message from abstract class');&#10;    } &#10;    &#10;    get publisher(): string {&#10;        return this._publisher.toUpperCase();&#10;    }&#10;    &#10;    set publisher(newPublisher: string) {&#10;        this._publisher = newPublisher;&#10;    }&#10;    &#10;    abstract printCitation(): void;&#10;}&#10;&#10;class Encyclopedia extends ReferenceItem {&#10;    &#10;    constructor(newTitle: string, newYear, public edition: number) {&#10;        super(newTitle, newYear);&#10;    }&#10;    &#10;    printCitation(): void {&#10;        console.log('message');&#10;    }&#10;}&#10;&#10;let test = new Encyclopedia('WorldPerdia', 1900, 10);&#10;test.printItem();</pre>
 </div>
همانطور که مشاهده می‌کنید درون یک کلاس abstract می‌توانیم متدهای abstract را نیز داشته باشیم؛ یعنی تنها امضای متد را تعیین کرده و پیاده‌سازی آن را به کلاس‌های مشتق شده واگذار کنیم.  </div> </div></div>
