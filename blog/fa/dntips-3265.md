<div class="postBody">تا قبل از اضافه شدن دیتاتایپ JSON به صورت توکار در MySQL، داده‌های JSON را تنها میتوانستیم با فرمت رشته‌ای، درون دیتابیس ذخیره کنیم: <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">CREATE TABLE tableName (&#10;jsonData CHAR(250) -- or VARCHAR, TEXT, BLOB&#10;);&#10;&#10;INSERT INTO tableName VALUES (&#10;'{ "name": "User1", "age": 41}'&#10;);&#10;&#10;SELECT * FROM tableName;&#10;&#10;{ "name": "User1", "age": 41}</pre>
 </div>
اما مشکل اینجاست که هیچ نوع اعتبارسنجی بر روی این دیتا صورت نخواهد گرفت؛ هیچ روشی برای مطمئن شدن از اینکه تگ‌ها به درستی استفاده شده‌اند، وجود ندارد و همچنین امکان جستجو را سخت خواهد کرد؛ زیرا مجبور خواهیم بود از Regular Expressions برای جستجوی درون متن‌های ذخیره شده استفاده کنیم: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">SELECT * FROM tableName&#10;WHERE jsonData REGEXP 'User1';</pre>
 </div> <br/> </div> <div>از نسخه MySQL 5.7.8 به بعد، می‌توانیم از نوع داده JSON برای ذخیره‌سازی محتوای JSON، استفاده کنیم. از این دیتاتایپ برای ذخیره‌سازی یک JSON document معتبر میتوان استفاده کرد: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">CREATE TABLE tableName (&#10;jsonData JSON&#10;);&#10;&#10;INSERT INTO tableName VALUES (&#10;'{ "name": "User1", "age": 41, "name": "User2"}'&#10;);&#10;&#10;SELECT * FROM tableName;&#10;&#10;{"age": 41, "name": "User2"}</pre>
 </div> <br/> </div> <div> <div>همانطور که مشاهده میکنید MySQL به صورت اتوماتیک یکسری نرمال‌سازی را روی دیتا اعمال کرده است:</div> <div> <ul> <li>ابتدا بررسی خواهد شد که سند JSON معتبر باشد؛ در غیر اینصورت ذخیره‌سازی با مشکل مواجه خواهد شد.</li> <li>از فیلدهایی که کلید تکراری دارند، صرفنظر خواهند شد. در مثال بالا دوبار فیلد name را مقداردهی کرده‌ایم. در اینجالت key/value دوم لحاظ شده‌است. البته میبایستی اصل first key wins لحاظ میشد، اما این مورد به عنوان یک باگ گزارش شده‌است و در نسخه‌های 8 به بعد رفع شده‌است (https://forums.mysql.com/read.php?3,660500,660500 - https://bugs.mysql.com/bug.php?id=86866).</li> <li>فاصله‌های اضافی بین کلیدها حذف شده‌اند.</li> <li>برای جستجوی بهتر، کلیدهای آبجکت JSON به صورت مرتب شده ذخیره شده‌اند. </li> </ul> </div> </div> <div> <br/> </div> <div> <b>جستجو درون JSON Document</b> </div> <div> <div>یک سند JSON، از یکسری کلیدها به همراه مقادیرشان تشکیل شده‌است. همچنین مقادیر میتوانند شامل اشیاء یا آرایه‌هایی به صورت تودرتو باشند. بنابراین به یک path جهت استخراج مقادیر نیاز خواهیم داشت. برای نوشتن یک path باید scope آن را تعیین کنیم که در توابع MySQL این scope به صورت پیش‌فرض، سند جاری میباشد که توسط علامت $ مشخص میشود. </div> <div>فرض کنید ساختار زیر را درون دیتابیس ذخیره کرده‌ایم: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">

 </div> <br/> </div> <div>برای دریافت دسته‌بندی‌های هر ردیف میتوانیم از تابع JSON_EXTRACT استفاده کنیم: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">SELECT &#10;    JSON_PRETTY(&#10;  JSON_EXTRACT(data, "$.category")&#10;    )&#10;FROM&#10;    experiments.productMetadata;&#10;&#10;/* &#10;  [&#10;    "fashion",&#10;    "men"&#10;  ]&#10;  [&#10;    "fashion",&#10;    "women"&#10;  ]&#10;  [&#10;    "fashion",&#10;    "men"&#10;  ]&#10;*/</pre>
 </div>
همانطور که مشاهده میکنید، تابع JSON_EXTRACT یک آرگومان دومی را نیز دریافت میکند که توسط آن میتوانیم path موردنظر را وارد کنیم و همانطور که عنوان شد، از $ برای دسترسی به سند جاری استفاده میکنیم. سپس در ادامه نام پراپرتی‌ای را که میخواهیم استخراج کنیم، تعیین کرده‌ایم. در اینجا چون ساختار ذخیره شده، به صورت شیء میباشد، به صورت مستقیم از $ و بعد از آن نقطه و سپس نام پراپرتی استفاده کرده‌ایم. میتوانیم عمق پیمایش را نیز بیشتر کنیم. به عنوان مثال برای دسترسی به المنت دوم از آرایه tag درون دیتا خواهیم داشت: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">JSON_EXTRACT(data, "$.tag[1]")&#10;JSON_EXTRACT(data, "$.description.shortDescription")</pre>
 </div> </div> <div> <br/> </div> <div>همچنین اگر کلید مقداری را که میخواهیم جستجو کنیم، بدانیم اما از کلید والد آن اطلاع نداشته باشیم، میتوانیم از * استفاده کنیم:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">SELECT &#10;JSON_EXTRACT(data, "$.*.shortDescription")&#10;FROM experiments.productMetadata;</pre>
 </div> </div> <br/> </div> <div> <b>JSON_KEYS</b> <br/> </div> <div>از این تابع جهت دریافت کلیدهای top level یک شیء JSON استفاده میشود:</div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">SELECT &#10;JSON_KEYS(data)&#10;FROM experiments.productMetadata;&#10;&#10;-- ["id", "new", "sku", "tag", "name", "image", "price", "rating", "category", "discount", "offerEnd", "saleCount", "variation", "description"]&#10;-- ["id", "new", "sku", "tag", "name", "image", "price", "rating", "category", "discount", "saleCount", "variation", "description"]</pre>
 </div> <br/> <div> <br/> </div> <div> همچنین میتوانیم path را نیز به عنوان آرگومان دوم آن تعیین کنیم:<span>  <br/> </span> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">SELECT &#10;JSON_KEYS(data, "$.description")&#10;FROM experiments.productMetadata;&#10;&#10;-- ["fullDescription", "shortDescription"]&#10;-- ["fullDescription", "shortDescription"]</pre>
 </div> <br/> </div> <div> <b>JSON_CONTAINS  </b> <br/> </div> <div>از این تابع برای جستجو استفاده خواهیم کرد و همانطور که از نام آن پیداست، در صورت وجود مقدار مورد جستجو، خروجی ۱ خواهد بود: <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">SELECT &#10;    JSON_CONTAINS(data, "10", "$.discount")&#10;FROM&#10;    experiments.productMetadata;&#10;&#10;-- 1&#10;-- 0</pre>
 </div> <br/> </div> <div> <b>JSON_CONTAINS_PATH</b> </div> <div> توسط این تابع میتوانیم بررسی کنیم که یک path یا یک یکسری path خاص درون JSON document وجود دارند یا خیر:<span>  <br/> </span> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">SELECT &#10;JSON_CONTAINS_PATH(data, "one", "$.description", "$.address", "$.website")&#10;FROM experiments.productMetadata;</pre>
 </div>
آرگومان اول این تابع، داکیومنتی است که میخواهیم جستجو کنیم. برای آرگومان دوم، یکی از دو مقدار one یا all را میتوانیم تنظیم کنیم. در ادامه لیستی از pathهایی را که میخواهیم جستجو کنیم، وارد کرده‌ایم. در حالت one، اگر تنها یکی از pathها درون داکیومنت JSON وجود داشته باشند، خروجی ۱ خواهد بود. اگر one را به all تنظیم کنیم، یعنی باید تمامی pathها، درون داکیومنت وجود داشته باشند تا خروجی ۱ شود؛ در غیراینصورت خروجی ۰ خواهد بود.  <br/> </div> <div> <br/> </div> <div> <b>JSON_SEARCH</b>  <br/> </div> <div>توسط این تابع میتوانیم position مقدار مورد جستجو را درون داکیومنت JSON پیدا کنیم: </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="Sql" name="code">SELECT &#10;    JSON_SEARCH(data, 'one', 'fashion')&#10;FROM&#10;    experiments.productMetadata;&#10;    &#10;-- "$.tag[0]"&#10;-- "$.tag[0]"</pre>
