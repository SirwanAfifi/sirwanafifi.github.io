<div class="postBody">همانطور که در <a href="/blog/fa/dntips-3420/">قسمت قبل</a>  اشاره شد، توابع نیز یکی از ویژگی‌های اصلی PowerShell هستند. قبل از بررسی بیشتر توابع بهتر است ابتدا با مفهوم script block آشنا شویم. script blocks به مجموعه‌ایی از دستورات گفته میشود که داخل یک بلاک قرار میگیرند. در واقع هر چیزی داخل {} یک script block محسوب میشود (البته به جز hash tables). به عنوان مثال در کد زیر از یک script block مخصوص، با نام فیلتر استفاده شده است که یک ورودی برای پارامتر FilterScript مربوط به دستور Where-Object میباشد. چیزی که این script block را متمایز میکند، خروجی آن است. به این معنا که خروجی آن باید یک مقدار بولین باشد:  <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">Get-Process | Where-Object { $_.Name -eq 'Dropbox' }</pre>
 </div>
script blocks را به صورت مستقیم درون command line هم میتوانیم استفاده کنیم. به محض تایپ کردن } و زدن کلید enter، امکان نوشتن اسکریپت‌های چندخطی را درون ترمینال خواهیم داشت. در نهایت با بستن script block و زدن کلید enter، از بلاک خارج خواهیم شد:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /Users/sirwanafifi/Desktop&gt; $block = {&#10;&gt;&gt; $newVar = 10&#10;&gt;&gt; Write-Host $newVar&#10;&gt;&gt; }</pre>
 </div>
با اینکار یک بلاک از کد را داخل متغیری با اسم block ذخیره کرده‌ایم. برای فراخوانی این قطعه کد میتوانیم از یک عملگر مخصوص با نام invocation operator یا call operator استفاده کنیم:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /Users/sirwanafifi/Desktop&gt; &amp; $block</pre>
 </div>
یا حتی میتوانیم از Invoke-Command نیز برای اجرای بلاک استفاده کنیم. همچنین از عملگر &amp; برای فراخوانی یک expression رشته‌ایی نیز میتوان استفاده کرد:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /Users/sirwanafifi/Desktop&gt; &amp; "Get-Process"</pre>
 </div>
البته این نکته را در نظر داشته باشید که &amp; قادر به پارز کردن (parse) یک expression نیست. به عنوان مثال اجرای کد زیر با خطا مواجه خواهد شد (برای حل این مشکل میتوانید بجای آن از Invoke-Expression استفاده کنید که امکان پارز کردن پارامترها را نیز دارد):<br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /Users/sirwanafifi/Desktop&gt; &amp; "1 + 1"&#10;or&#10;PS /Users/sirwanafifi/Desktop&gt; &amp; "Get-Process -Name Slack"</pre>
 </div> <div> <b> <br/> </b> </div> <div> <b>توابع</b> </div>
در قسمت قبل با نحوه ایجاد توابع آشنا شدیم. به این نوع توابع، basic functions گفته میشود و ساده‌ترین نوع توابع در PowerShell هستند. همچنین خیلی محدود نیز میباشند؛ یکسری ورودی/خروجی دارند. برای کنترل بیشتر روی نحوه فراخوانی توابع (به عنوان مثال دریافت ورودی از pipeline و…) باید از advanced functions یا توابع پیشرفته استفاده کنیم. در واقع به محض استفاده از اتریبیوتی با نام [()CmdletBinding] تابع ما تبدیل به یک advanced function خواهد شد. منظور از دریافت ورودی از pipeline این است که بتوانیم خروجی دستورات را به تابع‌مان pipe کنیم اینکار در basic function امکانپذیر نیست:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">Function Add-Something {&#10;    Write-Host "$_ World"&#10;}&#10;&#10;"Hello" | Add-Something</pre>
 </div>
اما با کمک advanced functions میتوانیم چنین قابلیتی را داشته باشیم:  </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">Function Add-Something {&#10;    [CmdletBinding()]&#10;    Param(&#10;        [Parameter(ValueFromPipeline = $true)]&#10;        [string]$Name&#10;    )&#10;&#10;    Write-Host "$Name World"&#10;}&#10;&#10;"Hello" | Add-Something</pre>
 </div>
یکی دیگر از ویژگی‌های advanced functions امکان استفاده فلگ Verbose حین فراخوانی دستورات میباشد. به عنوان مثال قطعه کد زیر را در نظر بگیرید:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">$API_KEY = "...."&#10;&#10;Function Read-WeatherData {&#10;    [CmdletBinding()]&#10;    Param(&#10;        [Parameter(ValueFromPipeline = $true)]&#10;        [string]$CityName&#10;    )&#10;&#10;    $Url = "https://api.openweathermap.org/data/2.5/forecast?q=$CityName&amp;cnt=40&amp;appid=$API_KEY&amp;units=metric"&#10;    Try {&#10;        Write-Verbose "Reading weather data for $CityName"&#10;        $Response = Invoke-RestMethod -Uri $Url&#10;        $Response.list | ForEach-Object {&#10;            Write-Verbose "Processing $($_.dt_txt)"&#10;            [PSCustomObject]@{&#10;                City               = $Response.city.name&#10;                DateTime           = [DateTime]::Parse($_.dt_txt)&#10;                Temperature        = $_.main.temp&#10;                Humidity           = $_.main.humidity&#10;                Pressure           = $_.main.pressure&#10;                WindSpeed          = $_.wind.speed&#10;                WindDirection      = $_.wind.deg&#10;                Cloudiness         = $_.clouds.all&#10;                Weather            = $_.weather.main&#10;                WeatherDescription = $_.weather.description&#10;            }&#10;        } | Where-Object { $_.DateTime.Date -eq (Get-Date).Date }&#10;        Write-Verbose "Done processing $CityName"&#10;    }&#10;    Catch {&#10;        Write-Error $_.Exception.Message&#10;    }&#10;}</pre>
 </div>
کاری که تابع فوق انجام میدهد، دریافت دیتای پیش‌بینی وضعیت آب‌وهوای یک شهر است. در حالت عادی فراخوانی تابع فوق پیام‌های Verbose را نمایش نمیدهد. از آنجائیکه تابع فوق یک advanced function است، میتوانیم فلگ Verbose را نیز وارد کنیم. با اینکار به صورت صریح گفته‌ایم که پیام‌های از نوع Verbose را نیز نمایش دهد:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">Read-WeatherData -CityName "London" -Verbose</pre>
 </div> <div>هر چند این مقدار را همانطور که در قسمت‌های قبلی عنوان شد میتوانیم تغییر دهیم که دیگر مجبور نباشیم با فراخوانی هر تابع، این فلگ را نیز ارسال کنیم. بیشتر دستورات native نیز قابلیت نمایش پیام‌های Verbose را با ارسال همین فلگ در اختیارمان قرار میدهند. بنابراین بهتر است برای امکان مشاهده جزئیات بیشتر حین فراخوانی توابع‌مان از Write-Verbose استفاده کنیم. در ادامه اجزای دیگر توابع را بررسی خواهیم کرد (بیشتر این اجزا درون یک script block نیز قابل استفاده هستند)</div> <div> <br/> </div> <div> <b>کنترل کامل بر روی ورودی‌های توابع</b> </div> <div>بر روی ورودی‌های یک تابع میتوانیم کنترل نسبتاً کاملی داشتیم باشیم. PowerShell یک مجموعه وسیع از قابلیت‌ها را برای هندل کردن پارامترها و همچنین اعتبارسنجی ورودی‌ها ارائه میدهد. به عنوان مثال میتوانیم یک پارامتر را mandatory کنیم یا اینکه امکان positional binding و غیره را تعیین کنیم. اتریبیوت Parameter در واقع یک وهله از System.Management.Automation.ParameterAttribute میباشد. میتوانید با نوشتن دستور زیر لیستی از خواصی را که میتوانید همراه با این اتریبیوت تعیین کنید، مشاهده کنید:  </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /&gt; [Parameter]::new()&#10;&#10;ExperimentName                  :&#10;ExperimentAction                : None&#10;Position                        : -2147483648&#10;ParameterSetName                : __AllParameterSets&#10;Mandatory                       : False&#10;ValueFromPipeline               : False&#10;ValueFromPipelineByPropertyName : False&#10;ValueFromRemainingArguments     : False&#10;HelpMessage                     :&#10;HelpMessageBaseName             :&#10;HelpMessageResourceId           :&#10;DontShow                        : False&#10;TypeId                          : System.Management.Automation.ParameterAttribute</pre>
 </div>
در ادامه یک مثال از نحوه هندل کردن ورودی‌های یک تابع را بررسی خواهیم کرد. تابع زیر یک لیست از URLها را از کاربر دریافت کرده و یک health check توسط دستور Test-Connection انجام میدهد. در کد زیر پارامتر Websites را با تعدادی اتریبیوت مزین کرده‌ایم. توسط اتریبیوت Parameter تعیین کرده‌ایم که ورودی الزامی است و همچنین مقدار آن میتواند از pipeline نیز دریافت شود. در ادامه توسط ValidatePattern یک عبارت باقاعده را برای بررسی صحیح بودن URL دریافتی نوشته‌ایم. از آنجائیکه ورودی از نوع آرایه‌ایی از string تعریف شده است، این تست برای هر آیتم از آرایه بررسی خواهد شد. برای پارامتر دوم یعنی Count نیز رنج مقداری را که کاربر وارد میکند، حداقل ۳ و حداکثر ۳ انتخاب کرده‌ایم:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">Function Ping-Website {&#10;    [CmdletBinding()]&#10;    Param(&#10;        [Parameter(Mandatory = $true, ValueFromPipeline = $true)]&#10;        [ValidatePattern('^www\..*')]&#10;        [string[]]$Websites,&#10;        [ValidateRange(1, 3)]&#10;        [int]$Count = 3&#10;    )&#10;    $Results = @()&#10;    $Websites | ForEach-Object {&#10;        $Website = $_&#10;        $Result = Test-Connection -ComputerName $Website -Count $Count -Quiet&#10;        $ResultText = $Result ? 'Success' : 'Failed'&#10;        $Results += @{&#10;            Website = $Website&#10;            Result  = $ResultText&#10;        }&#10;        Write-Verbose "The result of pinging $Website is $ResultText"&#10;    }&#10;    $Results | ForEach-Object { &#10;        $_ | Select-Object @{ Name = "Website"; Expression = { $_.Website }; }, @{ Name = "Result"; Expression = { $_.Result }; }, @{ Name = "Number Of Attempts"; Expression = { $Count }; } &#10;    }&#10;}</pre>
 </div>
یکی دیگر از اعتبارسنجی‌هایی که میتوانیم برای پارامترهای یک تابع انتخاب کنیم، ValidateScript است. توسط این اتریبیوت میتوانیم یک منطق سفارشی برای اعتبارسنجی مقادیر پارامترها بنویسیم. به عنوان مثال تابع فوق را به گونه‌ایی تغییر خواهیم داد که لیست وب‌سایت‌ها را از طریق یک فایل JSON دریافت کند. میخواهیم قبل از دریافت فایل مطمئن شویم که فایل، به صورت فیزیکی روی دیسک وجود دارد، در غیراینصورت باید یک خطا را به کاربر نمایش دهیم:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">Function Ping-Website {&#10;    [CmdletBinding()]&#10;    Param(&#10;        [Parameter(Mandatory = $true, ValueFromPipeline = $true)]&#10;        [ValidateScript({&#10;                If (-Not ($_ | Test-Path) ) {&#10;                    Throw "File or folder does not exist" &#10;                }&#10;                If (-Not ($_ | Test-Path -PathType Leaf) ) {&#10;                    Throw "The Path argument must be a file. Folder paths are not allowed."&#10;                }&#10;                If ($_ -NotMatch "(\.json)$") {&#10;                    throw "The file specified in the path argument must be either of type json"&#10;                }&#10;                Return $true&#10;            })]&#10;        [Alias("src", "source", "file")]&#10;        [System.IO.FileInfo]$Path,&#10;        [int]$Count = 1&#10;    )&#10;    $Results = [System.Collections.ArrayList]@()&#10;    $Urls = Get-Content -Path $Path | ConvertFrom-Json&#10;    $Urls | ForEach-Object -Parallel {&#10;        $Website = $_.url&#10;        $Result = Test-Connection -ComputerName $Website -Count $using:Count -Quiet&#10;        $ResultText = $Result ? 'Success' : 'Failed'&#10;        $Item = @{&#10;            Website = $Website&#10;            Result  = $ResultText&#10;        }&#10;        $null = ($using:Results).Add($Item)&#10;    }&#10;    &#10;    $Results | ForEach-Object -Parallel { &#10;        $_ | Select-Object @{ Name = "Website"; Expression = { $_.Website }; }, @{ Name = "Result"; Expression = { $_.Result }; }, @{ Name = "Number Of Attempts"; Expression = { $using:Count }; } &#10;    }&#10;}</pre>
 </div>
تابع Ping-Website را جهت بررسی فیچر جدیدی که همراه با دستور ForEach-Object استفاده میشود، تغییر داده‌ایم تا به صورت Parallel عمل کند؛ این قابلیت از نسخه ۷ به بعد به PowerShell اضافه شده است. از آنجائیکه این قابلیت باعث میشود script block مربوط به ForEach-Object درون یک context دیگر با نام <a href="https://devblogs.microsoft.com/powershell/powershell-foreach-object-parallel-feature/">runspace</a> اجرا شود. در نتیجه برای دسترسی به متغیرهای بیرون از script block نیاز خواهیم داشت از یک متغیر خودکار تحت‌عنوان using قبل از نام متغیر و بعد از علامت $ استفاده کنیم. همچنین آرایه مثال قبل را نیز به ArrayList تغییر داده‌ایم. زیرا در حالت قبلی امکان تغییر سایز یک آرایه با سایز ثابت را نخواهیم داشت. نکته دیگری که در مورد کد فوق میتوان به آن توجه کرد، نال کردن خروجی متد Add مربوط به آرایه‌ی Results است. همانطور که در قسمت قبل توضیح دادیم، از این تکنیک برای suppress کردن خروجی استفاده میکنیم و چون در اینجا خروجی متد Add یک عدد میباشد، با تکنیک فوق، خروجی را دیگر درون کنسول مشاهده نخواهیم کرد. توسط اتریبیوت Alias نیز نام‌های دیگری را که میتوان برای پارامتر Path حین فراخوانی تابع استفاده کرد، تعیین کرده‌ایم. لیست کامل اتریبیوت‌هایی را که میتوان برای پارامترهای یک تابع تعیین کرد، میتوانید در مستندات PowerShell ببینید.  <br/> </div> <div> <b>نکته</b>: اگر تابع فوق را همراه با فلگ Verbose فراخوانی کنیم، لاگ‌های موردنظر را درون کنسول مشاهده نخواهیم کرد؛ زیرا همانطور که اشاره شد script block درون یک context جدا اجرا میشود و باید متغیرهای خودکار مربوط به Output را مجدداً مقداردهی کنیم:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">Function Ping-Website {&#10;    [CmdletBinding()]&#10;    Param(&#10;        # As before&#10;    )&#10;    # As before&#10;    $Urls | ForEach-Object -Parallel {&#10;        $DebugPreference = $using:DebugPreference &#10;        $VerbosePreference = $using:VerbosePreference &#10;        $InformationPreference = $using:InformationPreference &#10;        &#10;        # As before&#10;    }&#10;    &#10;    # As before&#10;}</pre>
 </div> </div> <div> <b> <br/> </b> </div> <div> <b>قابلیت تعریف بلاک‌ها/توابع، به صورت تودرتو</b> <b> </b> <br/> </div> <div>درون توابع و script block امکان نوشتن بلاک‌های تودرتو را نیز داریم:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">$scriptBlock = {&#10;    $logOutput = {&#10;        param($message)&#10;        Write-Host $message&#10;    }&#10;&#10;    [int]$someVariable = 10&#10;    $doSomeWork = {&#10;        &amp; $logOutput -message "Some variable value: $someVariable"&#10;    }&#10;    $someVariable = 20&#10;&#10;    &amp; $doSomeWork&#10;}</pre>
 </div>
خروجی بلاک فوق  Some variable value: 20 خواهد بود؛ زیرا قبل از فراخوانی doSomeWork مقدار متغیر عددی someVariable را به ۲۰ تغییر داده‌ایم. برای script blocks این امکان را داریم که دقیقاً در همان جایی که بلاک را تعریف میکنیم، یک snapshot تهیه کنیم. در اینحالت خروجی، مقدار Some variable value: 10 خواهد شد:  <br/> </div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">$scriptBlock = {&#10;    $logOutput = {&#10;        param($message)&#10;        Write-Host $message&#10;    }&#10;&#10;    [int]$someVariable = 10&#10;    $doSomeWork = {&#10;        &amp; $logOutput -message "Some variable value: $someVariable"&#10;    }.GetNewClosure()&#10;    $someVariable = 20&#10;&#10;    &amp; $doSomeWork&#10;}</pre>
 </div>
یکسری بلاک‌های ویژه نیز درون توابع و script blockها میتوانیم بنویسیم که اصطلاحاً به name blocks معروف هستند:</div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">begin&#10;process&#10;end&#10;dynamicparam</pre>
 </div> <div>درون یک تابع اگر هیچکدام از بلاک‌های فوق استفاده نشود، به صورت پیش‌فرض بدنه تابع، درون بلاک end قرار خواهد گرفت. بلاک begin قبل از شروع pipeline اجرا میشود. process به ازای هر آیتم pipe شده اجرا خواهد شد. end نیز در پایان اجرا میشود. به عنوان مثال تابع زیر را در نظر بگیرید:</div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">function Show-Pipeline {&#10;    begin { &#10;        Write-Host "Pipeline start" &#10;    }&#10;    process { &#10;        Write-Host  "Pipeline process $_" &#10;    }&#10;    end { &#10;        Write-Host  "Pipeline end $_" &#10;    }&#10;}</pre>
 </div> <div>در ادامه یکسری آیتم را به ورودی این تابع pipe خواهیم کرد:</div> <div align="left" dir="ltr" style="direction: ltr;"> </div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /&gt; 1..2 | Show-Pipeline                                   &#10;Pipeline start &#10;Pipeline process 1&#10;Pipeline process 2&#10;Pipeline end 2</pre>
 </div> <div>همانطور که مشاهده میکنید، به ازای هر آیتم pipe شده، یکبار بلاک process اجرا شده است. همچنین برای دسترسی به مقدار آیتم pipe شده نیز از متغیر خودکار _$ استفاده کرده‌ایم (PSItem$ نیز به همین متغیر اشاره دارد). </div> <div> <br/> </div> <div>با توجه به توضیحات named blockهای فوق، اکنون اگر بخواهیم نسخه اول تابع Ping-Website را با pipe کردن یک آرایه فراخوانی کنیم، خروجی که در کنسول نمایش داده خواهد شد، تنها آیتم آخر از آرایه خواهد بود:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /&gt; "www.google.com", "www.yahoo.com" | Ping-Website                 &#10;&#10;Website       Result  Number Of Attempts&#10;-------       ------  ------------------&#10;www.yahoo.com Success                  3</pre>
 </div>
دلیل آن نیز این است که به صورت صریح کدها را درون بلاک process ننوشته بودیم. همانطور که عنوان شد، در حالت پیش‌فرض، بدنه توابع درون بلاک end قرار خواهند گرفت و تنها یکبار اجرا خواهند شد. بنابراین:</div> <div align="left" dir="ltr" style="direction: ltr;"> </div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">Function Ping-Website {&#10;    [CmdletBinding()]&#10;    Param(&#10;        # As before&#10;    )&#10;    process {&#10;        # As before&#10;    }&#10;}</pre>
 </div> <div>اینبار اگر تابع را مجدداً فراخوانی کنیم، خروجی مطلوب را نمایش خواهد داد:</div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /&gt; "www.google.com", "www.yahoo.com" | Ping-Website&#10;&#10;Website        Result  Number Of Attempts&#10;-------        ------  ------------------&#10;www.google.com Success                  3&#10;www.yahoo.com  Success                  3</pre>
 </div> <br/> </div> <div> <b>بلاک dynamicparam</b> </div> <div>از این بلاک برای تعریف پارامترهای داینامیک که به صورت on the fly نیاز هست ایجاد شوند، استفاده میشود. برای درک بهتر آن فرض کنید میخواهیم تابعی را بنویسیم که امکان خواندن یک فایل CSV را به ما میدهد. تا اینجای کار توسط Import-CSV به یک خط دستور قابل انجام است. اما فرض کنید میخواهیم به کاربر این امکان را بدهیم که یک ستون موردنظر از فایل را مشاهده کند. همچنین میخواهیم یک اعتبارسنجی هم روی نام ستونی که کاربر قرار است وارد کند نیز داشته باشیم. به عنوان مثال یک فایل CSV با ستون‌های name, lname, age داریم و کاربر میخواهد تنها ستون اول یک name را واکشی کند:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">PS /&gt; Read-Csv ./users.csv -Columns name</pre>
 </div>
برای اینکار میتوانیم با کمک dynamic param یک پارامتر را در زمان اجرا ایجاده کرده و مقادیری را که کاربر برای ستون‌ها مجاز است وارد کند، براساس هدر فایل CSV تنظیم کنیم:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">using namespace System.Management.Automation&#10;Function Read-Csv {&#10;    Param (&#10;        [Parameter(Mandatory = $true, Position = 0)]&#10;        [string]$Path&#10;    )&#10;    DynamicParam {&#10;        $firstLine = Get-Content $Path | Select-Object -First 1&#10;        [String[]]$headers = $firstLine -split ', '&#10;        $parameters = [RuntimeDefinedParameterDictionary]::new()&#10;        $parameter = [RuntimeDefinedParameter]::new(&#10;            'Columns', [String[]], [Attribute[]]@(&#10;                [Parameter]@{ Mandatory = $false; Position = 1 }&#10;                [ValidateSet]::new($headers)&#10;            )&#10;        )&#10;        $parameters.Add($parameter.Name, $parameter) &#10;        Return $parameters&#10;    }&#10;    Begin {&#10;        $csvContent = Import-Csv $Path&#10;        If ($PSBoundParameters.ContainsKey('Columns')) {&#10;            $columns = $PSBoundParameters['Columns']&#10;            $csvContent | Select-Object -Property $columns&#10;        }&#10;        Else {&#10;            $csvContent&#10;        }&#10;    }&#10;}</pre>
 </div>
