# آشنایی با LibMan در پروژه‌های ASP.NET Core

مدیریت پکیج‌های سمت کلاینت پروژه‌های جدیدی که با استفاده از قالب پیش‌فرض ایجاد می‌شوند، شامل یک پوشه با نام lib، در شاخه‌ی wwwroot هستند که حاوی این فایل‌ها می‌باشند: اینها به عنوان حداقل‌های ایجاد یک

<div class="postBody"><div> <div> <div> <b>مدیریت پکیج‌های سمت کلاینت</b> <br/> </div> </div> <div>پروژه‌های جدیدی که با استفاده از قالب پیش‌فرض ایجاد می‌شوند، شامل یک پوشه با نام lib، در شاخه‌ی wwwroot هستند که حاوی این فایل‌ها می‌باشند:</div> <div> <p style="margin-left: auto; margin-right: auto;"> <img src="/img/dntips/ebf0b2ef70f297c89879.png" style="display: block; margin-left: auto; margin-right: auto; cursor: default; height: 457px;"/> </p> </div> <div> <br/> </div> <div>اینها به عنوان حداقل‌های ایجاد یک وب اپلیکیشن، برای قالب انتخاب شده در نظر گرفته شده‌اند. اما فرض کنید بعد از مدتی می‌خواهیم ورژن bootstrap استفاده شده در پروژه را ارتقاء دهیم؛ در این حالت چندین انتخاب داریم:</div> <div> <br/> </div> <div> <ul> <li>دانلود مستقیم فایل موردنیاز و جایگزین کردن آن با نسخه‌ی فعلی</li> <li>حذف پوشه‌ی wwwroot/lib و نصب مجدد پوشه‌ها از طریق NPM یا Yarn</li> <li>استفاده از bower و سفارشی‌سازی مسیر قرار گرفتن فایل‌ها توسط browerrc.</li> </ul> </div> <div> <br/> </div> <div>روش اول، به نسبت ساده‌تر است؛ اما مشکل اینجاست که همه چیز به صورت دستی انجام خواهد گرفت. یعنی برای نسخه‌های بعدی همین روال باید مجدداً انجام شود. در روش دوم نیز مشکل اینجاست که مسیر قرار گرفتن پکیج‌های پروژه، از این به بعد node_modules خواهند بود و نیاز به یک تنظیم اضافی در فایل Startup.cs و مطلع کردن ASP.NET Core برای serve کردن فایل‌های سمت کلاینت است همچنین نیاز خواهد بود که تمامی ارجاعات داخل فایل Layout.cshtmlـ نیز از lib به node_modules تغییر پیدا کنند. در نهایت روش آخر نیز به دلیل <a href="https://snyk.io/blog/bower-is-dead/">منسوخ شدن bower</a> پیشنهاد نمی‌شود.</div> <div> <br/> </div> <div> <div> <b>استفاده از LibMan </b> </div> <div>LibMan یک قابلیت جدید است که از نسخه‌ی Visual Studio 2017 برای مدیریت پکیج‌های سمت کلاینت اضافه شده است. این ابزار به صورت cross platform تهیه شده است؛ یعنی در خارج از Visual Studio نیز قابل استفاده می‌باشد. در واقع این ابزار را می‌توانیم به صورت Globally روی سیستم خود نصب کنیم و از طریق خط فرمان همانند NPM از آن استفاده کنیم. <span>  </span> </div> </div> </div> <div> <br/> </div> <div> <b>نصب و استفاده از LibMan</b> </div> <div>این ابزار ابتدا توسط Mads Kristensen با عنوان<span> <a href="https://marketplace.visualstudio.com/items?itemName=MadsKristensen.Client-SideLibraryInstaller">Client-Side Library Installer</a> به صورت یک افزونه برای Visual Studio 2015 توسعه داده شد که در نهایت تیم ASP.NET این ابزار را  </span>به صورت توکار به Visual Studio 2017 اضافه کرد. در نتیجه اگر از نسخه‌ی 2017 ویژوال استودیو استفاده می‌کنید، برای استفاده از این ابزار نیاز به نصب پکیج خاصی نخواهید داشت. برای استفاده از این ابزار در سیستم‌عامل‌های به غیر از ویندوز نیز یک CLI تهیه شده است که از طریق خط فرمان قابل استفاده می‌باشد. برای نصب این ابزار کافی است ابتدا آن را به صورت سراسری نصب کنید:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">dotnet tool install -g Microsoft.Web.LibraryManager.Cli</pre>
 </div> <br/> </div> <div>قدم بعدی اضافه کردن فایلی با عنوان libman.json درون پروژه است. برای افزودن این فایل کافی است دستور زیر را در خطر فرمان وارد کنید:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">libman init</pre>
 </div> <br/> </div> <div>با صدور فرمان فوق فایل مربوطه درون پروژه ایجاد می‌شود که در واقع یک فایل json ساده برای مدیریت پکیج‌های سمت کلاینت است:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">{&#10;  "version": "1.0",&#10;  "defaultProvider": "cdnjs",&#10;  "libraries": []&#10;}</pre>
 </div> <br/> </div> <div>همانطور که مشاهده می‌کنید، می‌توانیم منبع دریافت پکیج‌‌ها را نیز تعیین کنیم که در حالت پیش‌فرض بر روی cdnjs تنظیم شده‌است و در واقع یک <a href="https://www.dntips.ir/search?term=CDN">Content Delivery Network</a> برای تعداد بیشماری پکیج سمت کلاینت است. درون آرایه‌ی libraries نیز می‌توانیم پکیج‌های موردنیاز خود را وارد کنیم. حتی برای هر پکیج هم می‌توانیم provider را override نمائیم. فرض کنید می‌خواهیم کتابخانه‌ی bootstrap را به پروژه اضافه کنیم. در اینحالت کافی است دستور زیر را برای نصب پکیج مربوطه صادر نمائیم:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">libman install bootstrap@4.3.1 --provider unpkg --destination wwwroot/lib/bootstrap</pre>
 </div> <br/> </div> <div>در نهایت فایل libman.json چنین ساختاری پیدا خواهد کرد:</div> <div> <div align="left" dir="ltr" style="direction: ltr;">
<pre language="CSharp" name="code">{&#10;  "version": "1.0",&#10;  "defaultProvider": "cdnjs",&#10;  "libraries": [&#10;    {&#10;      "provider": "unpkg",&#10;      "library": "bootstrap@4.3.1",&#10;      "destination": "wwwroot/lib/bootstrap"&#10;    }&#10;  ]&#10;}</pre>
 </div> <br/> </div> <div>برای نصب مجدد پکیج هم می‌توانید از دستور libman restore استفاده کنید؛ در این حالت دقیقا مانند Nuget، پکیج‌ها از روی فایل libman.json از provider مربوطه دانلود و به پروژه اضافه خواهند شد. در ادامه لیست دستورات موجود را مشاهده می‌کنید:</div> <div> <br/> </div> <div> <p style="margin-left: auto; margin-right: auto;"> <img src="/img/dntips/3016d9053e8089bab5a0.jpg" style="display: block; margin-left: auto; margin-right: auto; cursor: default; height: 537px;"/> </p> </div></div>
